# 企业级知识检索全量执行清单

## 1. 文档目的

本文档用于把“企业级知识检索全量改造方案”落成一份可执行、可排期、可验收的实施清单。

本文档不再重点解释方案原理，而是重点回答以下问题：

- 先做什么
- 后做什么
- 每一项具体要改哪里
- 需要补哪些数据
- 如何验证效果
- 什么条件下可以上线

建议使用方式：

- 作为项目排期清单
- 作为研发、产品、业务对齐清单
- 作为阶段验收清单
- 作为后续复盘和增量迭代基线

---

## 2. 总体目标

本次全量改造的目标不是简单“调几个 prompt”，而是把当前企业知识检索能力从“能搜到一些内容”提升为“能更稳定地回答找人、查流程、查知识、做总结”。

本次改造覆盖四个层面：

- 检索前理解
- 检索中召回与关系扩展
- 检索后总结与自检
- 数据治理、评测、上线机制

---

## 3. 项目范围

### 3.1 本次纳入范围

- 找人链路
- 知识检索链路
- 总结链路
- 企业术语和别名治理
- 文档引用关系利用
- 人-流程-文档关系建模
- Prompt 拆分与重构
- 评测样例集建设
- 回归验证与上线机制

### 3.2 本次暂不纳入范围

- 重做 OAuth、会话、消息发送主链路
- 大规模重构 Feishu API 封装
- 完全替换现有项目整体架构
- 一次性引入过重的全量知识图谱平台
- 引入新的复杂多租户权限系统
- 先做一个全局统一大评分器替换所有现有规则

---

## 4. 执行原则

- 优先做收益大、风险小、可快速验证的改造
- 先解决“回答不精准”的主要问题，再扩展复杂能力
- 先让找人和流程问题变稳，再扩展更泛化的知识问答
- 保留当前可用链路，避免一次性推翻重做
- 模型负责理解、归并、总结、自检，代码负责检索执行、边界和优先级控制
- 所有新增能力必须可观测、可回归、可降级

## 9. 风险清单

- [ ] 风险：前置标注过强，导致 query 被错误收敛
- [ ] 风险：图扩展过多，引入噪声材料
- [ ] 风险：群聊弱证据覆盖正式文档
- [ ] 风险：别名归一错误，误合并不同实体
- [ ] 风险：总结链路过度归纳
- [ ] 风险：改造后响应时延上升
- [ ] 风险：找人链路和知识链路互相影响
- [ ] 风险：日志不充分导致难以定位问题

### 风险应对

- [ ] 每项新能力都保留开关
- [ ] 默认只做 1 跳图扩展
- [ ] 强制文档优先级高于群聊
- [ ] 所有别名表先人工审核再上线
- [ ] 自检失败时默认降级而不是强答
- [ ] 灰度期间保留旧链路兜底
